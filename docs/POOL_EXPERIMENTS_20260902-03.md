## 0. 출발 질문

IsaacLab 정책이 SITL 에서는 되는데 실기에서 3 축이 2 Hz 로 떨었다. **왜 떠는가, 무엇이
지연을 만드는가, 학습에 무엇을 넣어야 하는가, 그리고 실기 재현을 막는 것이 정책인가 다른
것인가.** 세 세션은 이 넷을 순서대로 답했다.

---

## 1. 떨림의 기전 — "지연 + 포화" 인가, 다른 것인가 (09-02)

| 알기 위해 | 실험 | 결과 |
|---|---|---|
| EKF 수직 위치를 믿을 수 있나 (SITL 에서 얼었던 것) | 깊이 게이트: 압력을 자로 EKF z 회귀 | 기울기 1.005, R² 0.99 — **통과** |
| 실기 루프 지연은 얼마인가 | A2-heave / A2-yaw: 정책 빼고 사각파 여기 → 명령↔가속도 교차상관 | **τ = 80 ms** (yaw, r 0.81) |
| 이득 문제인가 지연 문제인가 | A1: 정책 이득 1.0 vs 0.5 | 진폭만 ×0.4~0.8, **주파수 그대로** → 이득으로 안 꺼진다 |
| 기체 공진·적분기·deadband 는 아닌가 | 개루프 bag 의 2 Hz 대역, 적분기 클램프, 동작점 | 전부 배제 |
| 정책이 실제로 포화하나 | 행동 포화 비율 | surge 73 %, sway 67 % 시간 **클램프에 붙음** |

**결론.** 80 ms 지연 아래서 포화(relay)된 정책이 만드는 limit cycle. 주파수는 지연이,
진폭은 포화 수준이 정한다. 위상 예산의 −180° 교차 2.4 Hz ≈ 실측 2.0~2.3 Hz.

## 2. 지연 DR 로 재학습하면 해결되나 (09-03 새벽)

| 알기 위해 | 실험 | 결과 |
|---|---|---|
| 행동 지연 40~80 ms + 관측 신선도 15 % 로 재학습한 `delayA` 가 relay 를 없애나 | 같은 자리·같은 프로토콜로 `fixplant` vs `delayA` 60 s 씩 | 포화 **58→7 %**(surge), 67→4 %(sway); 속도 0.10→0.17 m/s; 2 Hz ×0.24~0.66 |
| 남은 2 Hz 가 지연 DR 의 한계인가 미션 기하인가 | `heading_mode:=straight`(180° 선회 제거) 84 s | sway·roll·yaw 2 Hz **×0.13~0.25 로 붕괴**, EKF 발산 사라짐. **surge 만 6.7 N 그대로** |

**결론.** 지연 DR 은 통했다(포화 소멸). sway·roll·yaw 의 2 Hz 와 EKF 발산은 반복 선회가
만든 것이었다. surge 축 2 Hz 가 진짜 잔여다.

## 3. 지연은 어디서 생기나 (09-03 새벽 M1~M4, 오후 4차)

| 알기 위해 | 실험 | 결과 |
|---|---|---|
| τ 를 구간별로 나눌 수 있나 | M1 ping, M2 TIMESYNC, M3 명령→서보출력, M4 서보→자이로(FC 시계), chirp 로 τ 정밀화 | τ 85.3 (chirp); 테더 5.7 / 라우터+FC 수신 15 / **FC 내부+telemetry 64.4** / 액추에이터 ~0 |
| 그 64 ms 가 wrapper 가 더한 것인가 (§6 감사) | 학습 PC SITL: G1 telemetry 50 Hz, G2 100 Hz 폴링, G3 DO_SET_SERVO | FC 는 요청을 지킴; 틱 샘플링이 도착률을 숨기고 있었음; SITL 에선 백엔드 차이 없음 |
| FC 가 무엇인가 | 4차 Step 0 | **Navigator** — ArduSub 가 RPi 위에서 돎, 직렬 링크 없음 → baud 가설 기각 |
| 하행(FC→랩톱)은 얼마인가 | Step 1·2 transit 절대값(offset 2 회 측정, drift 보정, uint32 wrap 보정) | **하행 5~14 ms, 대표 ~10** — 모든 bag 에서 |
| 그러면 64 ms 는 어디인가 | 세 조각 뺄셈: 상행 M2/2, 하행 transit, FC 처리 = M3 − 둘 | **FC 처리 ≈ 58 ms(25 Hz) → 38 ms(50 Hz)**. 상행 10 + 하행 10 = 링크는 17 ms 뿐 |
| FC 처리의 구조는 | ArduPilot 소스 | servo 도장 = 메시지 생성 시각; **RC override 는 `rc_loop` 50 Hz 표본화**; 모터 400 Hz → RC 대기 10 + 슬롯 대기 20(25 Hz) 가 구조적 |
| RC override 경로가 범인인가 | Step 4b: 실기 DO_SET_SERVO A/B (yaw 채널 재계산) | M3 60 → **140 ms, ±170 ms 요동** — 더 나쁨. RC override 는 범인 아님. **백엔드 교체 폐기** |
| 25 Hz 에서 왜 주행마다 τ 가 다른가 (85 / 112 / 50 / 80) | 같은 설정의 반복 측정 비교 | **위상 고정**: 25 Hz telemetry 와 25 Hz 틱이 같은 주기라 액추에이션 대기·관측 대기가 각각 [0,40] 의 상수로 주행마다 다르게 굳는다. jitter 가 아니라 주행별 상수 |

**결론.** 64 ms 의 정체는 ArduSub 안이다. 온보드 이전·라우터 교체·전용 endpoint·백엔드 교체는
**전부 이유가 사라졌다.** wrapper 가 고착시킨 것은 하나 — telemetry 25 Hz = 제어 25 Hz 의
위상 고정 — 이고, 그것은 50 Hz 로 절반이 됐다.

## 4. telemetry 50 Hz 는 무엇을 바꾸나 (오후 4차)

| 알기 위해 | 실험 | 결과 |
|---|---|---|
| 정책이 보는 τ 가 줄어드나 | Step 2b chirp t25 vs t50 | t25 112 (이 주행) / t50 **79.7 ms**, r 0.90. 50 Hz 의 대푯값 80, 주행별 ±10 |
| FC 처리가 줄어드나 | Step 2 M3 | 80 → **60 ms** (−20; 슬롯 대기 위상 고정이 풀린 몫) |
| surge 2 Hz 가 움직이나 | Step 5 straight t25(실험 5) vs t50 17:26 | **5.69 → 6.50 N (×1.14). 안 움직였다 — 두 번 확인** |
| align 도 개선되나 | Step 5 align t25(새벽) vs t50 17:32 | 2 Hz ×0.4~0.56, 속도 0.10→0.18, 발산 78 s→없음(168 s). **단 t25 는 DVL 이 나쁘던 주행 — 개선의 대부분은 EKF 상태 차이** |
| FC 부하는 | SYS_STATUS load @50 Hz | 16.8 % |

**결론.** 50 Hz 는 τ 를 85→80 으로, 주행별 폭을 40→20 으로 줄인다. 그러나 **surge limit
cycle 은 τ 평균 10 ms 의 함수가 아니다.** 남은 길은 학습 PC 의 지연 DR 확대(주입 중심
τ−21 ≈ 59 ms, 주행별 ±10 을 덮는 폭)뿐이다.

## 5. 실기 재현을 막는 것은 정책인가 (오후 4차 Step 5 세부)

| 알기 위해 | 실험 | 결과 |
|---|---|---|
| 자유 주행 중 정책은 정상인가 | straight 17:26 다리별 분해 (34 다리) | **전부 4.0~4.7 s / 0.92~0.96 m / ±0.22 m/s, 포화 0~6 %** — 교과서 |
| "직진 거리가 다리마다 다르다" 는 무엇 탓인가 | 1차 시도(17:09) 다리별 EKF 거리 vs 사용자 관찰 | EKF 상 다리는 균일(0.93~0.96)한데 실제가 달랐다 → **틀린 쪽은 추정(EKF/DVL)** |
| EKF 는 방향이 틀린 건가 거리가 틀린 건가 | 다리별 변위 방향 − yaw | 전진 +1~8°, 후진 180±7° — **방향은 맞고 거리 축척이 비대칭**(≥0.9 m/55 s 편류) |
| "yaw 순증 +76°" 는 drift 인가 | yaw 시간축 | 0~55 s 는 ±2°/10 s 고정, 이후만 급증 = **벽에 눌린 것**, drift 아님 |
| 이륙 순간은 | align 1차(17:08) 위치 스텝 | >5 cm/tick 17 개 **전부 3~6 s(바닥에서 뜨는 순간)** |
| 얼마나 자주 나쁜가 | 정상 시도 4 회 + 중단 2 회 | 벽 2 회(17:08, 17:09), **DVL 불가로 EKF 끊겨 중단 2 회(17:23, 17:25)**, 깨끗 2 회(17:26 154 s, 17:32 173 s). 같은 자리·같은 설정 — **간헐적** |
| DVL 은 실제로 어떤 상태인가 | A50 REST 폴링 (align 17:32 앞 ~100 s, 450 표본) | 바닥 altitude **0.04 m < 최소 0.05** → 정지 lock 불가; 이륙 10 s 간 valid 44 %; 순항 **valid 82~88 %, 4 빔 96~100 %**, |v| 0.24 = EKF 0.22 |

**결론.** 정책과 guidance 는 시키는 대로 한다. 실기 재현의 병목은 **DVL(A50)** 이다 —
완전히 빠지면 미션이 안 서고, 반쯤 빠지면 거리 축척이 틀어져 벽을 만난다. 폴링이 답한 것:
(1) "beam3 상시 무효" 는 바닥에 놓였을 때만이다 — 고도 4 cm 는 A50 최소 5 cm 아래라 정지
lock 이 원리적으로 안 되고, 그것이 **이륙 순간 EKF 위치 점프**의 원인이다. (2) 순항 중엔
4 빔이 다 살아 있으므로 3-빔 편향 가설은 약해졌다. (3) 새벽 61 %(발산) vs 오늘 82~88 %
(173 s 정상) — **순항 valid ≥ ~80 % 가 정상 주행의 조건**이다. (4) 17:23/17:25 의 완전 상실은
센서보다 BlueOS extension/TCP 경로가 의심된다.

## 6. 종합

**해낸 것**
- 떨림의 기전 확정 (지연 + 포화 relay), 후보 넷 배제.
- 지연 예산 마감: 링크 17 / ArduSub 내부 ~40(50 Hz) / 액추에이터 0. 온보드·라우터·백엔드 교체 **불필요** 판정.
- wrapper 고착(§6 감사) 답변: 25 Hz 위상 고정이 실체였고 50 Hz 로 절반. 나머지 항목은 검증 후 무죄.
- 지연 DR 정책(delayA)이 실기에서 포화를 없앰. 50 Hz 에서 154 s / 173 s 무발산 주행 확보.
- 재현 도구 일습: deadtime_test(6 축·chirp), diag_loop_delay(closed/m3/m4/transit), diag_link_rtt(offset), transit_compare, RPi 프로브, 분석 스크립트, 실기 스크립트. 537 tests.

**부족한 것**
- surge 2 Hz 6.5 N — 실기에서 남은 유일한 진동. 50 Hz 로 안 움직임.
- DVL 간헐 불량 — 실기 재현의 실제 병목. 폴링 한 번(align 17:32)으로 정상 상태의 기준(82~88 %)은 잡았지만 나빠지는 순간의 기록은 아직 없음.
- 순항점 Jacobian 을 실기 bag 으로 잰 적 없음 (문턱 대비 "얼마나" 는 여전히 추정).
- M3/M4 도구의 채널 자동선택이 깊이유지 수직추진기를 고를 수 있음 (수동 재계산으로 우회).
