### 분석

`fixplant` 는 55 s 에 다리 3 개를 겨우 넘겼고 yaw 를 4.7 바퀴 **왕복**하며 제자리에서
요동했다. `delayA` 의 yaw 누적 −1357°(단조)는 왕복마다 같은 방향 180° 선회를 9 회
한 결과다 — **미션을 실제로 수행했다.** ω_yaw RMS 1.04 가 높은 것은 그 선회 때문이지
진동이 아니다.

기전 판정: A1(2026-09-02)에서 **이득만** 절반으로 했을 때는 포화가 58 → 62 % 로 그대로
였는데, **지연을 학습에 넣자 7 % 로 무너졌다.** 정책이 스스로 고주파 이득을 낮춘 것이고
relay limit cycle 의 근본 대응이 맞았다.

수용 기준 3 개 중 **2 개 통과** — 포화 < 10 %(yaw 18 만 미달), surge ≥ 0.2 근접(0.172),
**sway 2 Hz < 5 N 미달(10.8 N)**. 남은 것은 **sway·yaw** 두 축이다.

### 78 s 발산 — 정책이 아니다

| 구간 | \|v\| 중앙 | 자이로 \|ω\| | Bar30 상대깊이 |
|---|---|---|---|
| 60~75 s | 0.25~0.30 m/s | 0.17~0.98 rad/s | ±0.04 m |
| 80~90 s | **2.1~2.3 m/s** | 0.10~0.24 | −0.17~+0.06 |

자이로와 Bar30 은 정상인데 EKF 속도만 2 m/s 대로 튀었다. 4 m 수조에서 9.6 m 이동은
불가능하다 — **EKF 상태추정 발산**. `/brov/state.valid` 는 내내 true 였다(0 % invalid)
— **이 게이트는 발산을 못 잡는다.**

### 사후 분석 — 발산은 delayA 만의 사건이 아니다

두 주행 **모두** EKF 위치가 물리적 수조를 벗어났다:

| | 위치 범위 x / y | \|ω\| RMS | 수조 안전영역 |
|---|---|---|---|
| fixplant (60 s) | 1.97 / **1.82 m** | 1.61~1.68 rad/s | 3.30 / **1.10 m** |
| delayA (88 s) | 5.99 / 9.45 m | 1.05~1.29 rad/s | 〃 |

fixplant 도 15~30 s 구간에 이미 수조 폭을 넘었다. **78 s 발산은 내내 진행되던
드리프트의 끝**이지 갑작스러운 사건이 아니다.

원인은 **각속도**다. \|ω\| RMS 가 두 주행 내내 0.94~1.68 rad/s (54~96 °/s) 다 —
2 Hz 진동의 roll/pitch 성분에 다리마다 강제되는 180° 선회가 겹친다. 그 조건에서
DVL 은 빔 도플러가 뭉개지고 `VISION_POSITION_DELTA`(구간 위치차)의 프레임이 구간
안에서 돌아버린다.

**A50 이 이미 여유 0 으로 돌고 있다.** 정지 상태 REST 폴링
(`curl http://192.168.2.95/api/v1/velocity`, TCP 슬롯 안 씀):

```
altitude 0.66 m | 유효빔 3/4 ['0.73','0.71','X','0.76'] | valid=True
```

빔 3 번이 상시 무효다. 속도 해에 최소 3 빔이 필요하므로 **하나만 더 흔들리면 끊긴다.**

**단 불가피하지는 않다.** delayA 는 각속도를 오히려 낮췄다(1.6 → 1.1) — 진동이 준
만큼 DVL 에겐 쉬워졌다. 그런데도 발산한 것은 88 s 로 더 오래 돌았고 같은 방향 180°
선회를 9 회 반복했기 때문이다. 회전을 줄이면 DVL 도 산다 → `heading_mode:=straight`
(아래 "다음에 할 것" 참조).

**우리 숫자에 대한 영향.** 명령(wrench)·자이로 기반 지표 — 포화, 추진기 클램프,
2 Hz 대역(명령·응답), ω, τ/M2/M3/M4 — 는 EKF 와 무관하므로 **전부 온전하다.**
EKF 속도에 기대는 것은 v_e 와 surge 속도뿐인데, 60 s 에 위치가 ~0.7 m 초과
드리프트한 것은 속도 편의 **~0.012 m/s** 에 해당해 0.17 m/s 측정을 뒤집지 못한다.
55 s 창 A/B 비교는 그대로 선다.

## 실험 3 — M3/M4 지연 분해 (01:21, 40 s)

`runtime/a2_yaw.sh` (yaw, bias 1.0 ± 0.5 N·m, 1 Hz square). servo 토픽 배선 후 첫 측정.

```
M3  명령→서보출력 도착   85.0 ms,  r = +0.950   (servo2)
M4  서보→자이로 (FC 시계)  0.0 ms,  r = +0.325   (0 에서 단조 감소)
τ_total                   80.0 ms,  r = +0.809   (2026-09-02 재현)
```

**의도:** 80 ms 가 링크인지, FC 내부인지, 액추에이터인지 — 대응 수단이 구간마다 다르다.

**정합성 검사 통과.** M3 + M4 = 85 ms vs τ_total 80 ms (차 6 %).

| 구간 | 값 | 비중 |
|---|---|---|
| 링크 왕복 (M2) | 20.6 ms | 26 % |
| **FC 내부 + telemetry 생성 (M3−M2)** | **64.4 ms** | **80 %** |
| 액추에이터 + 자이로 (M4) | ~0 ms (< 20 ms 분해능) | ~0 % |

스트림 주기는 도착·FC 시계 모두 정확히 **25.0 Hz** — 요청대로 왔고 GCS 간섭 없음.
양자화 몫 ~20 ms 를 빼면 **~44 ms 가 FC 수신→override 적용→서보 출력** 경로다.

**분석 — 어제 결론의 정정.** 2026-09-02 는 80 ms 를 "통신·처리 경로 자체" 로 귀속했다.
쪼개 보니 **테더·라우터는 26 % 뿐이고 ESC·추진기는 0** 이다. 계획서 §0 이 걱정한
"ESC 소신호 응답 수십 ms"(포럼 실측 100 Hz 에서 130 ms)는 기각 — bias 로 계속 도는
프로펠러의 소신호 응답은 측정 분해능 아래다.

판정표에서 갈라진 곳: M4 ≥ 40 **미해당** → `RC_SPEED` 400 Hz A/B **불필요**(위험한
벤치 시험을 안 해도 된다). M2 ≥ 30 **미해당**. **잔차 지배 해당** → telemetry 주기
상향 + 라우터 교체가 유일하게 큰 몫.

> M4 의 r = 0.325 는 낮다(자이로 각가속도 잡음 + 협대역). 봉우리가 0 에서 단조
> 감소하므로 결론은 서지만, 정확히는 **τ_actuator < 20 ms** 로 읽어야 한다.

## 실험 4 — chirp (01:31, 40 s) — τ 확정

같은 yaw 프로토콜, 여기만 chirp 0.5→8 Hz.

**의도:** 1 Hz 협대역은 교차상관 봉우리 반폭이 ~250 ms 라 τ 를 흐리게만 잰다.
광대역으로 봉우리를 뾰족하게 만들어 τ 정밀화 + jitter 상한.

| | 1 Hz 사각파 | **chirp** |
|---|---|---|
| 피크 lag | 80.0 ms | 80.0 ms |
| **부그리드 보정** | 78.4 ms | **85.3 ms** |
| r | +0.809 | **+0.833** |
| 봉우리 반폭 | 120 ms | **60 ms** |
| 대비 (peak−min) | 1.17 | **1.30** |
| **lag 0 ms 의 r** | **+0.743** | **−0.205** |

**분석.** 마지막 줄이 결정적이다. 광대역 여기에서 **lag 0 의 상관이 음수** — 명령과
즉시 응답이 서로 반대라는 뜻이고, **지연이 없다면 나올 수 없다.** 사각파에서는
lag 0 에서도 +0.743 이라 봉우리인지 언덕인지 구분이 안 됐다.

부그리드 보정값 **85.3 ms** 가 M3(85.0) + M4(0) 과 일치한다. 사각파의 78.4 ms 는
협대역 때문에 왼쪽으로 당겨진 값이다. 예산이 소수점까지 닫힌다:

```
τ_total 85.3 ms = 링크 20.6 (M2) + FC 내부·telemetry 64.4 + 액추에이터 ~0 (M4)
```

jitter: r 이 0.833 까지만 오르는 잔여(1−r² ≈ 31 %)가 고정 지연으로 설명되지 않는
성분이고, M2 의 링크 jitter 폭(19.7 ms)이 그 크기와 부합한다.

## 실험 5 — `heading_mode:=straight` 재현 (~01:5x, 84 s)

delayA 를 `straight`(start yaw 고정, 180° 선회 없음)로 재현. 나머지 조건 동일.
bag `a4_delayA_straight`, 비교는 `a3_delayA-20260903-010900`(align), 둘 다 55 s 창.

**의도:** 실험 2 의 EKF 발산이 회전 때문인지 — 회전을 없애면 살아나는지.

### 회전이 무너졌다

| | align | **straight** |
|---|---|---|
| \|ω\| RMS (roll/pitch/yaw) | 0.50 / 0.40 / 1.04 rad/s | **0.15 / 0.16 / 0.11** |
| yaw 순증 (84 s) | −1374° | **+78°** |

### **EKF 발산이 사라졌다**

| | align | **straight** |
|---|---|---|
| 위치 범위 x / y | 5.99 / 9.45 m | **1.58 / 1.70 m** |
| 발산 | 75~90 s 에 15 s 만에 10.42 m | **없음 (84 s 완주)** |

수조 안전영역 3.30 × 1.10 m. straight 도 y 1.70 m 로 폭을 조금 넘지만 자릿수가
다르다. **align 이 78 s 에 터진 것보다 오래 돌고도 멀쩡했다.**

### 진동 — surge 만 남았다

| 축 | 명령 2 Hz | 응답 2 Hz |
|---|---|---|
| **surge** | 6.74 → **6.72 N (×1.00)** | 0.281 → 0.228 m/s² (×0.81) |
| sway | 10.83 → **2.74 N** (×0.25) | 0.641 → **0.128** (×0.20) |
| heave | 7.87 → 4.21 N (×0.53) | 0.297 → 0.162 (×0.55) |
| roll | 3.98 → **0.53 N·m** (×0.13) | 4.79 → **0.99 rad/s²** (×0.21) |
| pitch | 1.31 → 0.47 N·m (×0.36) | 2.17 → 1.01 (×0.47) |
| yaw | 1.68 → **0.26 N·m** (×0.15) | 1.66 → 0.51 (×0.31) |

포화: yaw 18 → **0 %**, 전 축 ≤ 4 %. 추진기 클램프 전 채널 **0 %**(T4 3 %).
v_e RMS [0.153, 0.097, 0.060] → **[0.111, 0.045, 0.028]**. 다리당 6.1 → **4.2 s**
(전환 9 → 13 회), \|v_d\| 평균은 둘 다 0.250 m/s.

> straight 의 body surge 평균이 −0.002 인 것은 왕복마다 부호가 바뀌기 때문이고
> (align 은 선회하므로 항상 전진), RMS 는 0.241 vs 0.236 으로 **속도는 같다.**

### 분석 — 2 Hz 의 출처가 둘이었다

**surge 축만 변하지 않았다(×1.00).** 나머지 다섯 축은 ×0.13~0.55 로 무너졌다.
즉 지금까지 본 2 Hz 는 두 갈래였다:

1. **surge 축의 dead-time limit cycle** — heading_mode 와 무관. τ 가 만든 것이고
   남아 있다. 6.7 N.
2. **sway–roll–yaw 커플링** — 반복되는 180° 선회가 여기(excitation)였다. 회전을
   없애자 함께 사라졌다.

`deadtime_result_to_training.md` §4c 가 "남은 것은 sway·yaw 두 축" 이라고 적은
것을 정정한다 — **그 두 축은 미션 기하가 만든 것이고, 진짜 남은 것은 surge 하나다.**

### DVL 은 고쳐지지 않았다

A50 REST 폴링(103 샘플, TCP 슬롯 안 씀): `velocity_valid` **61 %**, 빔별 무효
31~36 %. 주행 중 네 빔이 모두 1/3 씩 끊기고 속도해가 39 % 무효다.
**회전이 낮아 EKF 가 그 공백을 버틴 것이지 DVL 이 나아진 게 아니다.**
정지 상태에서 beam3 이 상시 무효였던 것과 함께, A50 점검이 별도 항목으로 남는다.
